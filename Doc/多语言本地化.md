# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 11 种语言｜英文为源文与兜底

## 1. 语言分层

本库按 NuGet 下载量分层维护运行时词表：下载量较高的核心组件对齐 NewLife.Core 的 31 种语言，其余组件维护 11 种语言（与 README 读者一致）。缺失译文在运行时自动回退英文，新增语言不需要改代码。

词表文件（10 个，另有英文源文兜底）：

- zh-Hans
- zh-Hant
- es
- de
- ja
- fr
- pt
- ru
- ko
- ar

## 2. 词表文件

- `MapApi/Locales`
- `NewLife.Map/Locales`

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 所有键在 10 份词表中都必须有译文，不允许留英文占位（品牌名、专有名词等本身即英文的除外）。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。
- 覆盖范围：异常消息、日志、控制台输出、接口返回的错误消息，以及程序集标题/描述、提供者与配置类的 `DisplayName` / `Description` 元数据。

> 源生成器随 `NewLife.Core` 包分发，**只有直接引用该包的项目才会执行**。项目经由其它项目间接获得 Core（传递引用）时，`Locales/*.yml` 不会被编译；此时应在该项目显式添加 `NewLife.Core` 的 `PackageReference`。MapApi 曾因缺少直接引用导致词表整表未生效。

### 2.1 运行时语言选择

```csharp
// 固定异常与接口消息语言；null 表示跟随当前 UI 文化
Localization.Culture = new CultureInfo("zh-Hans");

// 请求语言随上下文变化时，可单独固定日志语言
Localization.LogCulture = new CultureInfo("en-US");
```

MapApi 可在 `appsettings.json` 中配置，留空表示跟随操作系统：

```json
"Localization": {
  "Culture": "",
  "LogCulture": ""
}
```

MapApi 还会按请求头 `Accept-Language` 的 q 权重切换本次请求的界面语言，只修改 `CurrentUICulture`，不影响数字与日期格式；`Localization:Culture` 配置后固定语言，请求头不再生效。日志默认固定为宿主语言，避免随请求抖动。

```text
GET /Map/Ip?ip=
Accept-Language: zh-TW       → IP 為空
Accept-Language: fr-CA       → L'IP est vide.
Accept-Language: sw-KE       → 退守宿主语言
```

> 请求语言作用域直接使用 NewLife.Core 的 `NewLife.RequestCultureScope`，Map 不再本地维护实现。

### 2.2 带前缀日志

实例前缀（如 `[Baidu]`）必须**先翻译消息、再拼接前缀**。`Map` 的日志封装已经内置该规则：

```csharp
map.LogPrefix = "[Baidu]";          // 默认使用提供者类型名，如 [Baidu]
map.WriteLog("No available key.");  // 输出 [Baidu]没有可用密钥
map.WriteError("No available key.");// 错误级别，同样先翻译后拼接
```

不要对 `prefix + format` 整串调用 `L.T`，也不要直接交给 `Logger.Format` 查表——前缀随实例变化，整串永远匹配不到词条。自定义日志封装应使用 `Log.InfoPrefixed` / `Log.ErrorPrefixed` / `Log.WritePrefixed`。

### 2.3 程序集与提供者元数据

`AssemblyTitle` / `Description` 用**英文源文**，并把同一字符串作为键写入本程序集词表；中文给译文，其余语言给对应译文。显示与安装注册处调用 `L.T` 取得当前语言副本，原始元数据保持不变。

```xml
<AssemblyTitle>NewLife Map Component Library</AssemblyTitle>
<Description>A unified map component library that wraps Baidu, AMap, ...</Description>
```

- NuGet 元数据不随界面语言切换：`Description` 保持纯英文供反射使用，`PackageDescription` 承接中英双语描述，`PackageTags` 保留中英关键词。
- 提供者类的 `[DisplayName]`（如 `Baidu Map`、`AMap`）同样以英文为源文并进入词表，管理端下拉框与列表可直接翻译。

### 2.4 配置类元数据

配置类的 `[DisplayName]` / `[Description]` 用英文源文（`<summary>` 等代码注释仍用中文，服务开发者），译文写入本程序集词表。魔方 `ConfigController<T>` 会把描述翻译后按首句拆出显示名，例如 `Enable map. Defaults to true.` 在中文界面显示为「启用地图 / 默认true」。字段级翻译由所引用的魔方版本决定：词表与英文源文按本约定就绪后，随 Cube 的元数据本地化能力生效，MapApi 不需要再改代码。

```csharp
[Config("Map")]
[DisplayName("Map settings")]
public class MapSetting : Config<MapSetting>
{
    /// <summary>启用地图。默认true</summary>
    [Description("Enable map. Defaults to true.")]
    public Boolean Enable { get; set; } = true;
}
```

## 3. 新增一条消息

1. 代码中写英文源文：`throw new XException("Session {0} is closed.", sessionId);`；BCL 异常用 `L.T("English template", args)`；日志直接写英文模板（`Logger.Format` 自动翻译），带实例前缀时使用 `Log.InfoPrefixed` / `Log.ErrorPrefixed`。
2. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
3. 运行校验脚本确认键集合、占位符与格式说明符一致。

> 日志必须使用**格式字符串 + 参数**，不要使用字符串插值（`$"..."`）；插值后模板已展开，无法再按原文查表。

## 4. 校验

```powershell
# 词表键集合、占位符、孤儿键（源文含 *.cs 与 *.csproj，程序集标题/描述同样要能命中）
pwsh -File tools\check-locales.ps1 -LocaleDir NewLife.Map/Locales -SourceDir NewLife.Map
pwsh -File tools\check-locales.ps1 -LocaleDir MapApi/Locales -SourceDir MapApi

# README 语言切换行一致性
pwsh -File tools\sync-readme-languages.ps1 -Check

# NuGet 包版 README（README.nuget.md）与 README.md 同步，相对链接改写为 GitHub 绝对地址
pwsh -File tools\sync-readme-package.ps1 -Check
```

CI 的 localization job 会执行同一脚本。运行时生效性由单元测试兜底：

| 测试 | 覆盖 |
|------|------|
| `LocalizationTests.Translate_AllCultures_AreCompiled` | 10 种语言词表均已编译，标题译文非英文 |
| `LocalizationTests.Translate_AssemblyMetadata` | 程序集标题/描述按语言翻译，英文原样返回 |
| `LocalizationTests.Translate_DistanceUnit` | 带单位消息按语言格式化，如 `16米` / `16 m` |
| `LocalizationTests.WriteLog_*` | 带前缀日志先翻译后拼接前缀 |
| `LocalizationConfigTests.Translate_MapApiConfig` | MapApi 词表已注册，配置元数据按语言翻译 |

> 语言表由模块初始化器注册；测试若只读取元数据而不触达目标程序集的代码，需先执行一次 `RuntimeHelpers.RunModuleConstructor`。
